# Market discovery economics (Phase 3.0B)

Draft continuation of PR #23 (`ba173006498896682fcfe038a1205d7a14b12ad0`).
No deployment or production verification is included.

## Audit findings

The existing path is verified archive read -> normalize archive -> evidence-based
classifier -> strategy router -> existing constructors -> research_position ->
expiration max-loss capital filter -> deterministic comparison. REST and MCP both
use ArchiveResearchService.run and run_latest_market. Archive read permissions,
checksum, symbol identity and freshness remain the reader's responsibility.

Every accepted candidate has validated strikes, signed quantities, one expiration,
a signed package premium, spot and total dollar fees. Rejected/incomplete structures
remain excluded by the existing constructors and research validation.

| Candidate family | Existing premium/cost basis | Deterministic expiration | Historical metrics in run_market |
| --- | --- | --- | --- |
| Long call/put | Archived ask; existing zero-fee default | Available | Unavailable: intraday entry |
| Call/put debit spread | Existing midpoint debit rounded to cents; existing fee default | Available | Unavailable: intraday entry |
| Put/call credit spread | Natural bid/ask; existing $0.65 per-contract fee | Available | Unavailable: intraday entry |
| Iron condor/iron butterfly | Natural bid/ask; existing per-contract fee | Available | Unavailable: intraday entry |
| Put/call broken-wing butterfly | Natural bid/ask; existing per-contract fee | Available | Unavailable: intraday entry |
| Symmetric long butterfly | Supported by existing supplied-candidate research; not automatically generated by run_market | Available when supplied through that existing path | Unavailable: intraday entry |

Prices, zero slippage and constructor fee defaults are scenario assumptions, not
verified fills, commissions or executable prices. No strategy constructor, route,
classifier, capital filter or candidate ordering is changed. Direction, premium
and movement evidence still govern routes; no synthetic classification is added
to force all families into a single discovery result.

## Temporal limitation is material

run_market accepts archive observations strictly before the NYSE session close.
The existing historical adapter validates completed-session close-to-close
outcomes, with entry spot equal to that completed close. These are incompatible
entry contexts. Waiting until after close does not turn an earlier intraday entry
into a close entry. No current discovered family therefore receives non-null
historical EV, frequencies, quantiles or a sample fingerprint in this milestone.

The shared evidence builder now checks an optional exact entry observation against
the validated NYSE cutoff before any archive/history read. It returns
`intraday_entry_not_completed_session` for these market entries. The evaluator
also preserves `intraday_expiration_alignment_unavailable` and unavailable
historical scenarios. Calendar-invalid expirations fail their existing gate.
0DTE and unsupported daily horizons cannot bypass the entry gate. Daily analogs
are not selected for intraday candidates, regardless of sample count.

Existing explicit completed-session research_structure / compare_structures
retain their validated historical metrics, maturity, sample-size, horizon and
freshness checks. Their request contracts are unchanged.

## Additive response

Each `research_session.candidates[].research.historical_economics` contains:

- Deterministic expiration payoff/risk/breakevens via the shared evaluator.
- Null historical metrics with typed reasons, zero sample count, no fingerprint.
- Existing available_capital passed to expiration-risk eligibility; broker buying
  power remains null, even for candidates within the expiration-loss budget.
- Separate unavailable intraday, early-exit and execution/liquidity evidence.
- Pricing assumptions and entry observation; quote age remains unknown.
- An overnight-exposure flag for holding a later expiration until expiry.

`research_session.holding_policy` records the default preference to avoid overnight
exposure. It does not change expiration selection or pretend to validate an exit
before close. Eligible_for_consideration is always false. The old `status=complete`
means discovery completed, not that historical economics or execution is ready.

Shared grouping uses symbol/date/expiration/spot and a common exact entry timestamp.
One failed temporal evidence build is reused per compatible group. The initial
verified archive and classification history reads occur once in API orchestration;
there are zero additional archive/history reads for this unsupported temporal path.
The new `historical_comparison` exposes group indices and explicit non-comparability.
Discovery uses groups rather than quadratic pair lists; standalone comparisons
retain pairwise output. No ranking, recommendation or winner is introduced.

## Tests and production blockers

Fixture-based tests exercise the actual archive reader and REST/OAuth MCP transport,
all existing family constructors/research, budget filtering, temporal failure reuse,
0DTE, later expirations, later request clocks and absence of extra reads. Existing
regressions cover stale/missing archive failures, insufficient samples, incompatible
horizons and successful completed-session economics. No live provider validation.

Non-null intraday or early-exit EV requires independently validated entry-aligned
historical outcomes and, for early exits, historical option marks or validated
repricing inputs. That evidence is not present. Production deployment needs separate
approval; this draft neither changes production nor claims live opportunity readiness.
The next milestone is the design and validation of that intraday evidence path,
without fabricating option marks or weakening freshness.
